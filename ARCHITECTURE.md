# Архитектура Mining Proxy

Документ описывает текущую реализацию mining-proxy: компоненты, схему сети,
механику «откусывания» шар, отказоустойчивость и тестирование. Это основной
технический документ; краткая инструкция по использованию — в `README.md`.

---

## 1. Краткое описание

Программа-прокси прозрачно встраивается между ASIC-майнерами и их майнинг-пулом.
Она обрабатывает **только Stratum-трафик** (TCP), перехватывает `mining.submit`
и **перенаправляет часть шар** (0.1–100%) на другой пул/воркер (комиссия по
договору). Весь остальной трафик (DNS, NTP, DHCP и т.п.) идёт штатным маршрутом
и не затрагивается.

- Оригинальная шара **всегда** дублируется в реальный пул — майнер и пул не
  замечают подмены.
- Процент «слива» считается по **выполненным (принятым пулом)** шарам:
  `accepted / total * 100`.
- «Укуси и отпусти»: между укусами — пауза (в шарах или во времени), чтобы пул
  не пересоздавал соединение и не сбрасывался хешрейт.

## 2. Технологии

| Параметр | Решение |
|---|---|
| Язык | **Go** (module `mining-proxy`, Go 1.13+) |
| Зависимости | Только `gopkg.in/yaml.v3` (YAML). Весь сетевой код — стандартная библиотека |
| ОС сервера | **Ubuntu / Debian** (systemd) |
| Протокол майнинга | **Stratum V1 over TCP/TLS** (subscribe/authorize/submit) |
| Формат конфига | YAML: `host:port` + отдельные флаги `ssl` для upstream и целевого пула |
| Масштаб | Лимит одновременных соединений — 50 000 (`proxy/server.go`), буфер строки 4–16 КБ |

## 3. Схема сети

```
        площадка/облако
   ┌────────────────────────────┐
   │   сервер mining-proxy      │
   │   (Ubuntu/Debian, Go bin)  │
   │                            │
   │  ┌──────────────────────┐  │
   │  │ iptables NAT/DNAT    │  │
   │  │ (только порт пула)   │  │
   │  └──────────┬───────────┘  │
   │             ▼              │
   │  ┌──────────────────────┐  │
   │  │ mining-proxy         │  │  слушает 0.0.0.0:8443
   │  │ (Stratum-парсер)     │  │
   │  └───┬───────────┬──────┘  │
   │      │           │         │
   └──────┼───────────┼─────────┘
          ▼           ▼
   реальный пул   целевой пул
   (клиентский)   (наш воркер)
```

### Маршрутизация

```
Разрешённая подсеть ASIC ──▶ порт 3333 (порт реального пула)
                                   │
        ┌──────────────────────────┘ iptables DNAT (только --dport <порт пула>)
        ▼
   mining-proxy :8443 ──▶ реальный пул :3333   (весь трафик, прозрачно)
        │
        └────▶ целевой пул            (только «укушенные» шары, наш воркер)
```

- **DNS (53), NTP (123), DHCP (67/68)** и прочее НЕ матчатся DNAT-правилами
  (фильтр по порту пула) — идут штатным маршрутом.
- Приём трафика ограничен разрешёнными подсетями (`allowed_subnets`).

| `scripts` | Установка (systemd), интерактивный запуск, остановка | — |

## 5. Механика «кражи» шар

### 5.1. Параметры (конфиг)

| Параметр | Значение | Дефолт |
|---|---|---|
| `percentage` | доля шар для перенаправления | `5.0` (0.1–100) |
| `pause_shares` | режим «паузы в шарах» (точный %) | `true` |
| `interval_min/max_hours` | временная пауза между укусами (режим по времени) | `2` – `20` |
| `batch_size` | шар за один цикл кражи | `1` |
| `target_timeout_sec` | ожидание ответа целевого пула на шару | `30` |
| таймаут неактивности ASIC | сброс «умершей» сессии | `10 минут` |

### 5.2. Алгоритм

Входящий поток:

```
miner ──(line)──▶ pipeMinerToPool
                       │
                       ├── IsMinerSubmit? нет  ──▶ writeLine(реальный пул)
                       │
                       └── да ──▶ stealer.ShouldSteal()?
                                       │ no  ──▶ writeLine(реальный пул)
                                       │ yes ──▶ goroutine: ForwardToTarget(копия)
                                       │            + writeLine(реальный пул)  // оригинал ВСЕГДА
```

Два режима `ShouldSteal()` (`proxy/redirect.go`):

1. **`pause_shares: true` — «пауза в шарах».** Кусаем 1 шару каждые
   `round(100/percentage)` шар. Доля украденных строго ≈ `percentage%`,
   не зависит от скорости потока. Временные интервалы игнорируются.
2. **`pause_shares: false` — «пауза по времени».** Каждая шара попадает в
   рулетку `rand < percentage%`; после укуса — случайная пауза
   `[interval_min, interval_max]`. Фактический процент меньше заявленного.

В обоих режимах при недоступности целевого пула (failover) «укус» пропускается.

`ForwardToTarget()` (`proxy/redirect.go`) — сериализован мьютексом
`targetConnMu`, использует **персистентное** соединение с целевым пулом:
1. берёт/создаёт соединение (`subscribe` + `authorize` один раз);
2. переписывает воркера в `mining.submit` на `targetWorker` и меняет `id`
   на свой последовательный (`rewriteSubmit`);
3. шлёт и читает ответ; `result:true` инкрементирует `acceptedCount`;
4. при сбое — соединение сбрасывается (пересоздаётся на следующей шаре).

## 6. Учёт выполненной шары и мониторинг

- **Выполненная шара** — та, которую целевой пул принял: в ответе на
  перенаправленный `mining.submit` пришло `"result": true` без ошибки
  (`isAccepted()`). Reject (`result:false`) не засчитывается.
- Эндпоинт `GET /status` (только `127.0.0.1:9090`) отдаёт JSON:
  `stolen_shares`, `total_shares`, `stolen_percent`, `accepted_shares`,
  `accepted_percent` (**итоговая комиссия**), `next_cycle_in`, `uptime`,
  `target_pool`, `target_worker`, `target_up`, `forward_fails`.
- `GET /health` — `ok` для systemd/проб.

## 7. Отказоустойчивость

| Сценарий | Поведение |
|---|---|
| Целевой пул недоступен | **Failover**: шара не теряется, майнинг продолжается в реальный пул. `healthLoop()` каждые 60 с выполняет полный Stratum-handshake (dial + subscribe + authorize); при восстановлении флаг `targetUp` возвращается в true и «укусы» возобновляются. Ошибки перенаправления считаются в `forward_fails` |
| Целевой пул не отвечает в срок | Таймаут `target_timeout_sec`; соединение сбрасывается и пересоздаётся позже |
| ASIC «умер» / пропал | Idle-таймаут 10 минут → сессия закрывается, ресурсы освобождаются (`proxy/conn.go`) |
| Перегрузка сервера | Лимит соединений (semaphore 50 000): новые коннекты сверх лимита закрываются |
| Остановка сервиса | Graceful shutdown: закрывается listener, дожидаются активные сессии, чистится iptables, закрывается соединение с целевым пулом |

---

## 8. Безопасность

- Код полностью открыт, без скрытых действий; вся логика в исходниках.
- iptables ограничивается разрешёнными подсетями и конкретным портом пула.
- Мониторинг слушает только `127.0.0.1`.
- Для `ssl://`-пулов (upstream и целевой) TLS-проверка сертификата отключена
  (`InsecureSkipVerify`) — необходимость для публичных пулов с самоподписанными
  сертификатами. Риск осознан и зафиксирован в коде.

## 9. Развёртывание (Ubuntu/Debian)

```bash
sudo bash scripts/setup.sh          # сборка, установка, systemd-сервис
nano /etc/mining-proxy/config.yaml  # конфиг
systemctl start mining-proxy
systemctl enable mining-proxy
```

Без systemd (локально/разработка):

```bash
go run . --config config.local.yaml # конфиг генерирует scripts/start.sh
go run ./testrig/mockpool -listen 127.0.0.1:3333
go run ./testrig/mockpool -listen 127.0.0.1:3334
go run ./testrig/miner -proxy 127.0.0.1:8443 -worker вася3344 -sps 10
```

## 11. Тестирование

### Юнит-тесты

- `tests/stratum_test.go` — парсинг Stratum-сообщений, подмена воркера.
- `tests/redirect_test.go` — логика кражи: «не кусать до паузы», процент в
  режиме рулетки ~50%, точный процент в режиме «паузы в шарах» (~20%),
  учёт принятых шар (reject не засчитывается), failover при мёртвом целевом пуле.

### Интеграционный тест

`tests/integration_test.go` — e2e с двумя mock-пулами (реальный + целевой):

- реальный пул получает **все** шары (дублирование);
- целевой пул получает украденные шары с переписанным воркером;
- ровно 1 `subscribe` + 1 `authorize` на целевой пул (переиспользование);
- счётчик `accepted` совпадает с числом принятых целевым пулом.

### Стенд (testrig)

- `testrig/mockpool` — минимальный Stratum V1 пул (subscribe/authorize/submit
  отвечают `result:true`), запускается на 3333/3334.
- `testrig/miner` — эмулятор ASIC: subscribe/authorize + поток `mining.submit`
  с заданной частотой.

Запуск проверок: `go test ./...`, `go vet ./...`, `gofmt -l .`.
