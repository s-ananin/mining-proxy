# mining-proxy

Контекст расследования и рабочая версия комиссии на 40 ASIC:
[COMMISSION_CONTEXT_RU.md](COMMISSION_CONTEXT_RU.md).

Прозрачный Stratum-прокси со статистикой шар: перехватывает TCP майнеров
через iptables DNAT, проксирует в реальный пул без изменений трафика и
считает принятые/отклонённые/потерянные шары, отдавая их в JSON `/status`.

Прокси не парсит и не изменяет payload майнеров — это байтовая труба
(включая TLS майнера сквозь прокси). Мониторинг работает на уровне
Stratum V1 JSON-строк: `mining.submit` ↔ ответ пула.

## Возможности

- прозрачный перехват (`iptables DNAT` + `SO_ORIGINAL_DST`), майнеры
  не настраиваются вообще;
- счёт шар на воркерах: `submits / accepted / rejected / lost / staled`,
  процент принятия, сложность из `mining.set_difficulty`, хешрейт;
- `lost` — шары, на которые пул не ответил (обрыв/молчание);
- HTTP-мониторинг: `GET /status` (JSON) и `GET /health`;
- fail-open: при остановке правила DNAT снимаются, майнеры уходят
  в пул напрямую, майнинг не прерывается.

## Сборка и запуск

```sh
go build -o mining-proxy .
./mining-proxy --config config.local.yaml
```

Конфиг: см. [`config.example.yaml`](config.example.yaml). Обязательные
поля при `setup_iptables: true` — `allowed_subnets`; `upstream_pool`
нужен как fallback и для DNAT-фильтра по порту.

Порядок старта: конфиг → listener (порт занимается до DNAT, чтобы
майнер не получил RST в промежутке) → iptables → приём соединений →
мониторинг. При SIGINT/SIGTERM соединения дожидаются, правила снимаются.

## Мониторинг

```sh
curl -s http://127.0.0.1:9090/status | jq
curl -s http://127.0.0.1:9090/health
```

Пример `/status`:

```json
{
  "status": "ok",
  "listen_addr": "0.0.0.0:8443",
  "totals": {
    "connections_active": 12,
    "connections_total": 340,
    "submits": 1200, "accepted": 1198, "rejected": 2,
    "lost": 0, "staled": 0,
    "accepted_percent": 99.83,
    "difficulty": 16,
    "hashrate": 1374389534720
  },
  "pools": [ ... ],
  "workers": [ ... ],
  "nat": { ... }
}
```

`monitor_addr` по умолчанию слушает только `127.0.0.1` — наружу не
выставляйте без firewall.

## systemd

```sh
sudo cp mining-proxy /usr/local/bin/
sudo cp config.example.yaml /etc/mining-proxy/config.yaml   # и поправить
sudo cp mining-proxy.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mining-proxy
journalctl -u mining-proxy -f
```

## Тесты

Перед первой комиссионной шарой прокси ждёт подтверждения авторизации и
фактической сложности из `mining.set_difficulty` не более секунды.
Подтверждение `suggest_difficulty` само по себе не подтверждает смену сложности.
Меньшая сложность допускается; при большей прокси просит коррекцию и ждёт
её в пределах того же таймаута. Неотправленный бюджет сохраняется.
Неудачная подготовка или отклонённая шара приостанавливает комиссию только
на этом соединении на 90 секунд. Если пул сбросил задание (`clean_jobs`)
или изменил extranonce, старая шара не отправляется как комиссионная.
После возврата авторизации обычные шары ждут завершения восстановления.
Повторные попытки комиссии на адрес пула после неотвеченной шары
приостанавливаются на 10 минут, в том числе при разрыве TCP до таймаута.
Успешный `authorize` не снимает эту паузу; обычная добыча продолжается.
Занятый допуск к авторизации пропускает изъятие без задержки обычной шары.
В интервальном логе `sent_work` и `accepted_work` разделены; скорость
`accepted` и диагностический `steal_ths` считаются по принятой работе.
Процент комиссии считается от суммы сложностей
принятых обычных шар. Расход бюджета учитывает фактическую сложность комиссии
на пуле. Отклонённая работа повторно планируется на следующем тике;
неотправленная возвращается в бюджет. Долг за последнюю целую шару
уменьшает бюджет следующих тиков. `commission.effective_percent` показывает
фактически принятую комиссионную работу в процентах от принятой обычной
работы за текущее суточное окно. Он заменяет прежний `target_today` в шарах.

После ответа на последнюю комиссионную шару при исчерпанном бюджете прокси
сразу запрашивает авторизацию основного воркера. Возврат завершается после
подтверждения пула и нового задания; сложность, extranonce и notify передаются
майнеру в исходном порядке без изменения `clean_jobs` и job ID. Шары проходят
в пул без локальной браковки; его ответы пересылаются без изменений. При отказе или отсутствии
подтверждения/задания за 10 секунд соединение закрывается для переподключения.

```sh
go test ./...        # unit + e2e (mock-пул → прокси → клиент)
go test -race ./...
```

Структура:

- `config/` — YAML-конфиг и валидация;
- `proxy/` — слушатель, сессии, парсер Stratum V1, реестр статистики;
- `iptables/` — настройка/снятие DNAT, статус перехвата;
- `monitor/` — HTTP `/status`, `/health`;
- `tests/` — интеграционные сценарии (accept/reject/lost, raw-passthrough);
- `testrig/` — мок-пул и эмулятор майнера.

## Средний хешрейт в `/status`

`avg` содержит окна `10m`, `60m`, `24h`. В каждом — четыре значения в **TH/s**:

- `pools_ths` — принятая работа всех обычных пулов;
- `commission_ths` — принятая пулом работа комиссии;
- `pools_reject_ths` — отклонённая работа обычных пулов;
- `commission_reject_ths` — отклонённая работа комиссии.

Комиссия отделена от обычных пулов. Полный принятый хешрейт равен
`pools_ths + commission_ths`. Отклонённая работа считается по сложности
отправленной шары; потерянные ответы в reject не включаются.
После переавторизации сложность первой комиссионной шары может быть ещё
неизвестна. Если пул сообщает её до ответа на шару, work учитывается по
первому полученному значению. Если уведомления нет, accepted/rejected
учитывается, но work этой шары исключается из хешрейта (в логе —
`fee difficulty unknown; work excluded`). Это консервативная оценка:
сложность майнера не подставляется вместо неизвестной сложности комиссии.
Отправка шары не задерживается. До уточнения сложности резерв бюджета
сохраняется, чтобы неизвестный work не приводил к лишним изъятиям.

История общая для всех соединений и сохраняется при реконнектах, включая
пулы без активных соединений. Сумма сложностей переводится в хеши через
`2^32` и делится на длительность окна, включая время простоя. До заполнения
окна используется фактическое время с запуска процесса. История хранится
в памяти с точностью до секунды и сбрасывается при перезапуске.

Из JSON `commission` убраны `work_issued`, `work_accepted`, `work_rejected`,
`pools`, `window_worker`; внутренний учёт работы продолжает использоваться
для бюджета и диагностики в логах.

## Проверка пула и справедливость изъятия

**Проверка пула отдельным соединением.** Прежде чем брать комиссию на адресе
пула, прокси сам открывает к нему короткое TCP-соединение (без TLS):
`mining.subscribe` → `mining.authorize(commission_worker)` и ждёт ответа.
Майнер в этом не участвует.

- пул принял воркера → комиссия на адресе разрешена, перепроверка в фоне раз
  в час без перерыва изъятия;
- `result=false`, разрыв или молчание после authorize → адрес исключён на
  30 мин, при повторных отказах пауза удваивается до 6 ч;
- сетевая ошибка до authorize → повтор через 1 мин, вердикт не меняется.

Белого списка нет: пул комиссии может сменить IP, новый адрес проверяется
при первом же соединении майнера. Результаты — в `commission.pool_checks`.

**Обучение на боевых соединениях.** Неотвеченная комиссионная шара (таймаут
или разрыв) ставит пул на паузу 10 мин; каждая следующая неудача подряд
удваивает паузу до 6 ч. Зачтённая комиссионная шара сбрасывает серию.

**Без двойного списания.** Отклонённая и неотвеченная комиссионная работа
считается израсходованной: шара майнера уже потрачена, повторно на следующем
тике она не берётся. Возвращается в бюджет только работа, которая так и не
была отправлена (шара ушла майнеру).

**Без догоняющих всплесков.** Неизрасходованный остаток бюджета переносится
на следующий тик не более чем в размере 50% его порции; остальное сгорает
(`commission.forfeited_work`). Поэтому после провала (пул недоступен, шторм
реконнектов) изъятие не превышает 1.5× нормы за интервал.

`commission.effective_percent` — принятая пулом комиссия от принятой работы;
`commission.charged_percent` — сколько работы фактически списано с майнеров
(включая отклонённые и потерянные комиссионные шары).
